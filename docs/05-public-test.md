# 公开测试准备

用途：把「准备公开测试」拆成可执行的检查项与一场读者测试的操作手册。与 `04-worklog.md` 的分工：那份记录做过什么与证据，这份记录上线前必须做什么、读者来了怎么观察。

## 1. 上线前检查清单

按顺序执行，前一步不通过就不要进入下一步。

| # | 项 | 命令 / 位置 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 数据库指向真实实例 | `DATABASE_URL` | 启动日志与应用行为一致；`npm run db:migrate` 显示目标库 |
| 2 | 对象存储指向真实桶 | `STORAGE_DRIVER=s3` + `S3_*` | 服务器日志出现 `[storage] driver=s3 bucket=…`；`npm run verify:storage` 11/11 |
| 3 | 旧文件迁移 | `npm run storage:migrate` | 输出「新上传 / 跳过」数之和等于 `storage/pdfs` 文件数 |
| 4 | 密钥与账号 | `.env.local` 或部署平台环境变量 | `AUTH_SECRET` 为随机长串；GitHub 与 SMTP 凭据齐全时对应功能可用 |
| 5 | 构建与启动 | `npm run build` → `npm start` | 退出码 0、0 条追踪警告；生产模式下 `npm run verify:smoke` 63/63 |
| 6 | 负载回归 | `npm run verify:load` | 160 个请求、0 个 5xx |
| 7 | 作者账号 | `npm run db:seed` | Florence 与 α 均可登录后台 |
| 8 | 备份与恢复演练 | `pg_dump`（Postgres）或 `npm run db:backup`（PGlite） | 恢复出的库逐表行数与清单一致；PDF 目录一并备份 |
| 9 | 定时备份 | 部署平台 cron | 每日一次，保留至少 7 份；**未配置时不要对外开放** |
| 10 | 版权入口 | `/legal/takedown` | 页面可访问，联系方式真实可收信 |
| 11 | 回滚方案 | 部署平台 | 上一版镜像/提交可一键回退；数据库迁移可前滚不可回滚，改动前先备份 |

第 4 项里两个可选项影响功能完整性，缺了要在页面上如实说明而不是留空按钮：

- **GitHub 登录与绑定**：需要 GitHub App 的 client id / secret，Redirect URI 填两个（`/api/auth/callback/github` 与 `/api/me/github/callback`）。
- **邮件投递**：未配置时验证与重置链接只写入服务器日志（`src/lib/mailer.ts`），公开测试阶段等于「密码找回不可用」。开放注册前应至少有一个可用通道，或接受这个限制并在注册页说明。

## 2. 读者测试方案

目标：拿真实读者的行为回答一个问题——读者能不能在没有指导的情况下找到论文、读完、并在正确的位置留下评论。

- 人数：2 至 3 名，最好是正在读论文的人（研究生、工程师、研究者各一）。
- 时长：每人 30 至 40 分钟，单独进行，中途只记录不提示。
- 环境：生产形态（`npm start` 或真实部署），不要用开发服务器——开发模式与生产模式的行为差异已经在第 14 轮暴露过一次。

任务清单（逐条给出，不做解释，观察他如何理解）：

1. 找到一篇你最近读过的论文，加进书架。
2. 打开它，在第 3 页某一句上留一条评论。
3. 把这条评论改成匿名发布，再发一条回复。
4. 换到深色主题，刷新页面确认设置还在。
5. 在个人信息里改一次昵称，再改回来。
6. 找到「我发过的评论」列表，删掉其中一条。

观察记录（每场一份，字段固定便于比较）：

| 字段 | 记录方式 |
| --- | --- |
| 卡住的位置 | 任务编号 + 屏幕上的原话，不写解释 |
| 完成时间 | 每个任务从开始到完成或放弃的秒数 |
| 提问次数 | 每次问「这个在哪」都计数 |
| 放弃的任务 | 编号与原因（读者原话） |
| 报错与异常 | 页面提示、控制台报错、500 |
| 主动评价 | 读者自己说的感受，原话照抄 |

## 3. 结果从哪里看

行为数据大部分已经在库里，不需要额外埋点：

| 问题 | 数据来源 |
| --- | --- |
| 有没有真的读到论文 | `reading_progress` 的 `progress` 与 `updated_at` |
| 有没有发评论、发在哪 | `comments` 的 `page` / `y_norm` / `quote` / `kind` |
| 有没有用匿名 | `comments.is_anonymous` |
| 搜索是否被用、有没有失败 | 服务器日志里 `/api/papers/search` 的状态与 `error` 字段 |
| 页面是否报错 | 生产服务器日志（`verify:load` 已经覆盖 5xx 这一类） |

判断是否继续做社区、AI 或推荐，建议用三条门槛（先定标准再看数据，避免事后解释）：

1. **留存**：2 名读者在一周内主动第二次打开，并且不是因为被要求。
2. **互动密度**：有评论的论文里，平均每条评论被另一个人点赞或回复的比例超过 0。
3. **成本**：在没有推广的情况下，服务器与存储的月成本低于可接受上限，且备份与恢复脚本实际跑过一次。

三条都不到时不加功能，先解决卡点；第 2 条不到通常是「评论位置或可见性不清楚」，不是功能不够。

## 4. 当前已知限制（对外说明的素材）

- 头像由昵称的前两个字符生成，底色与字色可在资料页选择（默认 #002FA7 底 + 白字）；不支持上传图片或外链头像。
- 邮件通道未配置时，密码找回与邮箱验证链接只写服务器日志。
- OpenAlex 对自由文本检索按 IP 限流（实测 `Retry-After` 可达数小时）；限流期间显示缓存结果并标明缓存时间，没有缓存时明确报错。
- 没有 PDF 的论文只保存元数据，阅读入口指向来源网站。
- 站内通知在页面加载时读取，没有实时推送。
