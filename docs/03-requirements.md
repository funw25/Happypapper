# HappyPaper 当前需求整理

版本：v0.1
更新日期：2026-10-13
关联文档：docs/02-project-roadmap.md

本文档整理当前已经提出的产品想法，将其转换为可讨论、可设计、可开发、可验收的需求。尚未确认的内容统一放在“待确认问题”中。

## 1. 产品范围

HappyPaper 是一个论文阅读与位置化评论平台。用户阅读论文时，可以在页面、段落或选中文本处发布评论；后来阅读同一篇论文的用户，可以在对应位置看到这些评论和弹幕。

当前明确需要规划的内容：论文搜索与阅读入口；网站整体视觉和页面设计；邮箱注册登录；GitHub 账号登录；两个管理员账号 Florence、α；个人主页和个人资料编辑；用户匿名状态；邮箱地址管理；用户评论和弹幕的显示控制。

## 1.1 论文获取方式

用户不应被要求先手动上传 PDF。首选流程是搜索论文元数据，系统从论文来源解析公开可用的论文页面或 PDF，用户确认后直接进入阅读器。

推荐优先级：

1. 搜索 arXiv、DOI 或其他开放论文索引。
2. 显示标题、作者、摘要、年份、来源和可用性。
3. 找到开放获取 PDF 后，导入论文元数据并缓存 PDF。
4. 用户进入阅读器阅读和发布评论。
5. 如果没有公开 PDF，显示论文详情和外部来源链接，而不是伪装成可阅读状态。
6. 用户上传 PDF 作为补充入口，主要用于私有论文或索引未收录的论文。

论文搜索和 PDF 获取是两个不同状态：一篇论文可以“已找到元数据但没有可用 PDF”，也可以“已有 PDF 但尚未公开”。

PAPER-001 用户可以按标题、作者、DOI 或 arXiv ID 搜索论文。
PAPER-002 搜索结果显示论文标题、作者、摘要、年份、来源和 PDF 可用状态。
PAPER-003 用户可以从搜索结果进入论文详情页。
PAPER-004 对有开放 PDF 的论文，用户可以直接开始阅读。
PAPER-005 系统记录论文来源和许可证或开放获取信息。
PAPER-006 外部 PDF 获取失败时显示可理解的错误，并允许重试或打开来源网站。
PAPER-007 同一 DOI 或 arXiv ID 不重复创建论文记录。
PAPER-008 用户上传 PDF 仍然可用，但不作为主要阅读路径。

推荐的用户界面文案是“搜索论文”“从来源导入”“上传本地 PDF”，而不是让用户先理解文件存储流程。

## 2. 用户角色

### 2.1 普通用户

普通用户可以注册和登录、使用邮箱或 GitHub 登录、编辑个人资料、阅读论文、发布和管理自己的评论、选择评论是否匿名，以及管理自己的评论展示设置。

### 2.2 匿名访客

匿名访客可以浏览公开论文、阅读论文内容、查看允许公开的评论和弹幕，但不能发布评论、点赞、回复或修改个人资料。

### 2.3 管理员

系统首版设置两个管理员：

| 管理员名称 | 角色 |
| --- | --- |
| Florence | admin |
| α | admin |

管理员可以访问管理后台、处理举报、隐藏或恢复评论、禁言用户、维护敏感词，以及处理论文下架和版权投诉。

管理员名称和账号应通过数据库种子或部署初始化脚本创建，不能只写在前端页面中。

## 3. 视觉与页面设计

### 3.1 设计目标

网站整体需要具有统一的视觉语言，使论文阅读、评论和用户操作保持清晰层级。

设计优先级：论文内容可读；评论位置和上下文清楚；操作路径简单；页面风格统一；支持不同主题和屏幕尺寸。

### 3.2 视觉设计系统

需要建立统一的设计变量：

- 色彩：页面背景、阅读区、评论侧栏、正文、次要文字、边框、主色、强调色、成功/警告/错误色、浅色主题和深色主题
- 排版：页面标题、区块标题、论文标题、正文、辅助说明、按钮文字、标签、评论正文、用户昵称
- 布局：页面最大宽度、阅读器与评论侧栏比例、页面内边距、区块间距、导航高度、工具栏高度、移动端断点
- 组件：顶部导航、搜索框、按钮、标签、输入框、下拉菜单、弹窗、评论卡片、头像、提示、空状态、加载状态、错误状态

### 3.3 主题需求

UI-001 系统支持浅色主题。
UI-002 系统支持深色主题。
UI-003 系统支持跟随系统主题。
UI-004 用户可以手动切换主题。
UI-005 主题设置保存后，刷新页面仍然保持。
UI-006 主题切换不改变论文内容和评论数据。
UI-007 深色主题下正文、评论、按钮和表单仍具有足够对比度。

### 3.4 页面需求

需要统一设计：首页、论文列表页、论文详情页、论文阅读器页、登录页、注册页、个人主页、个人资料编辑页、隐私设置页、管理后台、错误页、空状态页和加载状态。

UI-008 页面之间使用统一的导航和返回逻辑。
UI-009 桌面端阅读器优先保证论文区域的可读宽度。
UI-010 弹幕不能遮挡关键论文内容。
UI-011 重要操作必须有成功、失败和加载反馈。
UI-012 页面支持键盘操作和基本无障碍对比度。

## 4. 注册与登录

### 4.1 邮箱账号

AUTH-001 用户可以使用邮箱和密码注册。
AUTH-002 一个邮箱地址只能绑定一个主账号。
AUTH-003 用户可以使用邮箱和密码登录。
AUTH-004 用户可以退出登录。
AUTH-005 登录失败时显示明确但不泄露敏感信息的错误。
AUTH-006 用户可以发起忘记密码流程。
AUTH-007 修改邮箱或重置密码时需要重新验证身份。

待确认：是否要求注册邮箱验证，以及密码复杂度规则。

### 4.2 GitHub 登录

AUTH-008 用户可以使用 GitHub OAuth 登录。
AUTH-009 GitHub 用户首次登录时自动创建账号，或进入资料补全流程。
AUTH-010 GitHub 登录后可以设置本站昵称。
AUTH-011 已有邮箱账号可以绑定 GitHub 账号。
AUTH-012 用户可以在安全设置中解绑 GitHub，但必须保留一种可用登录方式。
AUTH-013 GitHub 登录失败或取消时，页面显示可理解的提示。

待确认：是否同步 GitHub 头像和昵称；是否允许同一账号绑定多个 OAuth 提供商；是否要求邮箱已验证才能发布评论。

## 5. 个人主页与资料编辑

### 5.1 个人主页

个人主页可以展示头像、昵称、个人简介、贡献信息、评论数量、收藏论文、公开评论和账号隐私状态。

PROFILE-001 用户可以访问自己的个人主页。
PROFILE-002 其他用户可以访问允许公开的个人主页。
PROFILE-003 用户可以编辑自己的个人资料。
PROFILE-004 用户不能编辑其他用户的个人资料。
PROFILE-005 用户保存资料后刷新页面仍显示最新内容。

### 5.2 可编辑字段

| 字段 | 是否可编辑 | 默认可见性 |
| --- | --- | --- |
| 昵称 | 是 | 公开 |
| 头像 | 是 | 公开 |
| 个人简介 | 是 | 由用户控制 |
| 登录邮箱 | 是，但需验证 | 不公开 |
| GitHub 账号 | 可绑定/解绑 | 不公开 |
| 匿名发布设置 | 是 | 不公开 |
| 评论展示设置 | 是 | 不公开 |

PROFILE-006 需要明确昵称是否唯一。
PROFILE-007 需要统一定义昵称修改后历史评论是否同步显示新昵称。
PROFILE-008 邮箱修改后需要重新验证。
PROFILE-009 用户不能在个人主页看到其他用户的登录邮箱。

## 6. 匿名与隐私设计

“匿名状态”需要拆成不同设置，不能只设计成一个模糊开关。

### 6.1 发布身份

PRIVACY-001 用户可以选择评论使用公开昵称或匿名身份发布。
PRIVACY-002 匿名评论对普通读者显示为“匿名用户”或系统生成的匿名标识。
PRIVACY-003 管理员在处理举报时可以看到评论的真实作者。
PRIVACY-004 匿名只影响署名，不影响评论内容、位置和审核状态。
PRIVACY-005 需要确定修改默认匿名设置是否影响历史评论。

建议 MVP 规则：默认设置只影响新发布的评论；历史评论单独提供修改入口。

### 6.2 评论和弹幕可见性

“显示/不显示自己的评论弹幕”建议拆成两个设置：

1. 个人主页评论公开：别人是否能从个人主页看到评论列表。
2. 论文阅读器显示：评论是否出现在论文阅读器的侧栏和弹幕中。

PRIVACY-006 用户可以关闭个人主页中的评论列表。
PRIVACY-007 关闭个人主页评论展示不会删除评论。
PRIVACY-008 用户可以控制新评论是否进入弹幕流。
PRIVACY-009 关闭弹幕展示不会影响评论保存。
PRIVACY-010 用户可以删除自己的评论。
PRIVACY-011 删除评论后，普通读者无法在阅读器和个人主页看到该评论。
PRIVACY-012 管理员可以根据审核需要查看被隐藏或删除的记录。
PRIVACY-013 可见性设置保存后，刷新页面和重新登录仍然生效。

建议 MVP 规则：评论默认在论文阅读器中可见；用户可以选择是否在个人主页展示自己的评论；匿名只影响署名；用户删除评论后普通用户不可见；管理员保留必要审核记录。

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 阅读公开论文 | 可以 | 可以 | 可以 |
| 发布评论 | 不可以 | 可以 | 可以 |
| 点赞和回复 | 不可以 | 可以 | 可以 |
| 编辑自己的资料 | 不可以 | 可以 | 可以 |
| 编辑他人资料 | 不可以 | 不可以 | 需另行定义 |
| 删除自己的评论 | 不可以 | 可以 | 可以 |
| 删除他人评论 | 不可以 | 不可以 | 可以 |
| 查看举报队列 | 不可以 | 不可以 | 可以 |
| 处理举报 | 不可以 | 不可以 | 可以 |

## 9. 页面与设置入口

建议页面结构：

~~~text
/u/[name]                  个人主页
/settings/profile          资料编辑
/settings/account          邮箱、密码、GitHub 绑定
/settings/privacy          匿名、评论和弹幕可见性
/admin                     管理后台
~~~

资料编辑页负责昵称、头像、简介。账号安全页负责邮箱、密码和 GitHub。隐私设置页负责匿名和内容可见性，避免把所有设置堆在个人主页中。
