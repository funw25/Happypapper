# HappyPaper 项目拆解与实施路线图

版本：v1.0
更新日期：2026-10-13

## 1. 项目定义

HappyPaper 是一个面向论文阅读的“位置化评论 + 弹幕”平台。读者可以在论文页面、段落或选中文本处留下评论；后来读者阅读到相同位置时，可以看到这些评论，并进行回复、点赞和举报。

核心体验是让论文的阅读位置成为讨论的上下文。首版需要验证：读者是否愿意留下有上下文的评论，后来读者是否能在正确位置看到评论，以及评论是否真正帮助理解论文。

## 2. 当前项目状态

仓库已经具备：

- Next.js App Router、React、TypeScript 项目骨架
- Auth.js 邮箱密码登录和注册
- PGlite/Drizzle 数据库、迁移和种子脚本
- arXiv ID / DOI 论文导入
- PDF 上传、缓存和 HTTP Range 读取
- 论文列表、搜索、标签、详情页
- 收藏和阅读进度
- PDF.js 阅读器基础实现
- 评论、点赞、举报相关 API 与数据表基础
- 位置锚点工具：页码、归一化坐标、文本引用、前后文匹配

当前重点缺口：

- 阅读器中的弹幕浮层、位置标记和侧栏交互
- 评论发布、回复、筛选、排序和实时更新的完整闭环
- 锚点在不同缩放、不同 PDF 文本层下的恢复质量
- 管理后台、内容审核和版权投诉流程
- 端到端测试、错误处理、部署和监控

现有 `docs/00-mvp-spec.md` 是功能规格，`docs/01-stack-decision.md` 是技术选型；本文档负责把它们转化为实施顺序和验收计划。

## 3. 用户流程

### 普通读者

1. 搜索论文或通过 DOI/arXiv ID 导入。
2. 查看元数据并进入阅读器。
3. 恢复上次阅读位置，翻页、缩放或选择文本。
4. 输入评论类型和内容，选择显示方式后发布。
5. 在页面上看到位置标记，在侧栏看到当前页附近的评论。
6. 阅读其他评论，点赞、回复或举报。
7. 离开后再次进入，恢复阅读进度。

### 论文贡献者

贡献者通过 DOI/arXiv 元数据或上传 PDF 创建论文记录。上传者必须确认拥有分发 PDF 的权利；默认上传内容为私有，确认后才可公开。

### 管理员

管理员查看举报队列，处理违规评论、禁言用户、维护敏感词，并处理版权投诉或论文下架请求。

## 4. MVP 功能边界

| 模块 | 必须完成 | 验收结果 |
| --- | --- | --- |
| 论文 | 搜索、导入、上传、详情 | 用户能打开一篇可阅读论文 |
| 阅读 | PDF 翻页、缩放、恢复进度 | 重新进入后回到上次页面 |
| 定位 | 页码 + 页内归一化坐标 + 文本引用 | 缩放后评论仍位于合理位置 |
| 评论 | 选中文本发布、按页发布、删除自己的评论 | 发布后刷新仍存在 |
| 展示 | 位置标记、评论侧栏、短暂浮层 | 当前页和附近页评论可见 |
| 互动 | 点赞、回复、举报、类型筛选、排序 | 操作结果即时反馈且刷新后保持 |
| 实时 | 同一论文页面的新评论 SSE 推送 | 另一浏览器能收到新评论 |
| 账号 | 匿名阅读，登录后评论 | 未登录用户不能发布 |
| 管理 | 举报列表、隐藏评论、禁言 | 违规内容不再展示 |
| 合规 | 上传权利确认、版权投诉入口 | 可记录并处理下架请求 |

推迟功能：关注用户、领域社区、专家认证、AI 总结与问答、语义搜索、引用图谱、移动端原生应用。

## 5. 阅读器与定位设计

阅读器同时提供三种互补视图：

1. **位置标记**：在页面右缘按 `y_norm` 显示标记，点击打开评论。
2. **评论侧栏**：显示当前页及相邻页面的评论，按页面位置排列。
3. **弹幕浮层**：新评论或进入页面时短暂飘过，用户可以关闭或降低密度。

位置标记和侧栏是主要阅读功能，浮层异常时不能影响论文阅读和评论查询。

评论保存多种定位信息，并按可靠性回退：

1. `page + y_norm`：始终可用的页面级定位。
2. `quote + quote_prefix + quote_suffix`：尽量恢复到原句。
3. `char_start + char_end`：同一文本层中的精确区间。
4. `block_id`：预留给未来的段落级索引。

渲染时先用文本引用匹配当前文本层，成功后重新计算 DOM 位置；失败则使用归一化坐标；都不可用时定位到页面顶部并标记降级状态。扫描版 PDF 只承诺页面和坐标定位，并显示提示。

发布规则：内容限制为 1 至 500 个字符；选中文本自动带入引用；发送前校验页面、坐标和锚点版本；限制发送频率；失败时保留草稿。

## 6. 技术架构

继续使用 Next.js 单体应用：

```text
浏览器（React / PDF.js）
        │ REST + SSE
Next.js 页面与 Route Handlers
        │
领域服务（论文、锚点、评论、审核、实时）
        │
Drizzle → Postgres / PGlite
StorageAdapter → 本机磁盘（后续可换 S3）
```

Route handler 只负责鉴权、参数解析和 HTTP 响应；业务逻辑集中在 `src/server/` 或同等领域模块中。首版使用长驻 Node 进程，不把 SSE 放在无状态 Serverless 函数中。

技术选择：Next.js、React、TypeScript、Tailwind CSS、PDF.js、Drizzle、Auth.js、PostgreSQL/PGlite、SSE。多实例时再加入 Redis Pub/Sub。

建议目录：

```text
src/app/              页面与 API 路由
src/components/       UI 与阅读器组件
src/db/               schema、连接、查询
src/lib/anchor.ts     锚点格式和文本匹配
src/lib/papers/       元数据导入、PDF 缓存
src/server/           评论、审核、实时、存储领域服务
scripts/              迁移、种子、worker、冒烟测试
docs/                 规格、架构、路线图和运行手册
```

## 7. 数据与接口

核心表：`users`、`papers`、`comments`、`comment_likes`、`reports`、`reading_progress`、`favorites`、`banned_words`。评论通过 `parent_id` 支持回复，不另建回复表。

评论查询必须带 `paper_id + page` 条件，并按 `y_norm`、热度或时间排序。点赞和回复计数应在事务中更新。管理员权限必须在服务端验证，不能只隐藏前端按钮。

核心 API：

```text
GET    /api/papers?q=&tag=&sort=&cursor=
POST   /api/papers
GET    /api/papers/:id
GET    /api/papers/:id/pdf
GET    /api/papers/:id/comments?page=&spread=&kind=&sort=
POST   /api/comments
DELETE /api/comments/:id
POST   /api/comments/:id/like
DELETE /api/comments/:id/like
POST   /api/comments/:id/report
GET    /api/papers/:id/stream
GET/PUT /api/papers/:id/progress
POST/DELETE /api/papers/:id/favorite
GET/PATCH /api/admin/reports[/:id]
PATCH  /api/admin/comments/:id
POST   /api/admin/users/:id/mute
```

`POST /api/comments` 至少校验登录状态、论文存在、页面范围、坐标范围、内容长度、评论类型、父评论是否属于同一论文，以及用户是否被禁言。

## 8. 分阶段开发计划

### 阶段 0：基线

- 完善 `.env.example`、运行说明和迁移流程
- 确认开发账号、PDF worker 和示例论文可用
- 补充错误页、加载态和空状态

验收：新环境按 README 操作后，可以登录、导入论文并打开 PDF。

### 阶段 1：阅读器闭环

- 稳定 PDF.js 翻页、缩放和 fit width
- 保存滚动位置和阅读进度，处理快速翻页的旧渲染取消
- 完善文本层 span 索引与选区计算
- 在 100%、150% 和窗口变化后验证锚点

验收：同一评论在不同缩放下仍落在对应段落附近。

### 阶段 2：评论闭环

- 发布框、评论类型和显示模式
- 当前页及相邻页评论加载
- 位置标记与侧栏联动
- 删除、回复、点赞、举报
- 未登录、禁言、限流、重复提交和网络失败处理

验收：登录用户能从“选中文本”完成发布、刷新和重新定位。

### 阶段 3：弹幕与实时

- 实现同页评论 SSE
- 新评论进入浮层队列，按密度限制同时展示数量
- 关闭弹幕、类型筛选、时间/热度排序
- 断线重连和重复事件去重

验收：两个浏览器打开同一论文，一个发布评论，另一个能在合理延迟内看到；重连不会产生重复评论。

### 阶段 4：审核与合规

- 管理员举报队列、评论隐藏/恢复和禁言
- 敏感词检测、人工复核状态和审核日志
- 上传权利确认、版权投诉和下架记录

验收：隐藏内容对普通读者不可见，管理员能查看处理记录；下架后不能继续公开提供 PDF。

### 阶段 5：公开测试

- 加入真实论文和种子讨论
- 观察评论发布率、锚点命中率、阅读完成率和举报率
- 修复常见定位失败和阅读器性能问题
- 做数据库与 PDF 备份恢复演练

## 9. 测试与验收

必测场景包括：登录权限、导入失败、重复论文、有/无文本层 PDF、跨文本项选区、重复引用消歧、缩放和刷新、空/过长/敏感评论、重复点赞、跨论文回复、SSE 断线重连、普通用户访问管理员 API、Range 请求和下架后的 PDF 访问。

测试分层：

- 单元测试：`anchor.ts` 的归一化、引用匹配和坐标计算
- API 测试：权限、参数校验、事务和状态变更
- 端到端冒烟：登录、导入、打开、评论、刷新、恢复进度
- 浏览器测试：不同窗口宽度、缩放和 PDF 样本
- 手工验收：真实论文阅读体验和评论可读性

每次合并前运行：

```bash
npm run typecheck
npm run build
npm run db:migrate
npm run db:seed
```

## 10. 部署与运维

首次部署时准备长驻 Node 环境和 PostgreSQL，配置认证密钥、数据库连接、PDF 存储目录和站点地址；先运行迁移，再创建管理员并修改默认密码；配置 HTTPS、上传大小限制、反向代理和备份。

重点监控：PDF 加载失败率、评论发布成功率、锚点命中/降级率、SSE 连接和重连、API 5xx、数据库错误、磁盘占用、举报量和处理时间。

扩展触发条件：多实例部署时加入 Redis；PDF 容量增长时切换 S3；搜索变慢时引入专用索引；文本抽取复杂时追加独立 worker，保持 API 契约不变。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| PDF 文本层质量差 | 保留页面坐标回退并显示降级提示 |
| PDF 版权不清晰 | 默认私有、权利确认、投诉和下架流程 |
| 弹幕遮挡正文 | 密度上限、关闭开关，侧栏作为主入口 |
| 评论刷屏和攻击 | 登录写入、限流、敏感词、举报和禁言 |
| 多实例实时不一致 | 首版单实例，扩展时引入 Pub/Sub |
| 本机磁盘丢失 | StorageAdapter、备份，生产环境可换对象存储 |
| 锚点算法升级破坏旧评论 | anchor_version、兼容回退和迁移脚本 |

## 13. 第一周执行顺序

1. 运行现有项目，确认数据库、PDF worker 和示例账号正常。
2. 对 `PdfReader` 做完整手工测试，记录加载和选区定位问题。
3. 先完成“发布评论 -> 刷新 -> 重新显示”的非实时闭环。
4. 再完成位置标记、侧栏联动和筛选排序。
5. 最后接入 SSE 浮层、在线人数和断线重连。
6. 每完成一段就补一个可重复的冒烟测试，不把所有功能堆到最后一起验收。

项目完成的标准不是页面功能数量，而是读者可以稳定打开论文，在正确位置看到有用的历史讨论，同时系统能够控制低质量内容和论文文件的风险。
