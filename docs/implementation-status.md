## M3 评论事务与重连恢复

点赞、取消点赞、删除及管理员隐藏/恢复现在先锁论文、再锁评论。业务变更、计数和通知在同一事务提交，避免并发重复操作产生不一致状态。隐藏、恢复或删除回复会同步重算根评论的回复数。

`node scripts/verify-comment-mutations.mjs` 已对生产产物通过测试，包括 12 次并发点赞只创建一条记录及通知、12 次并发取消点赞清除通知，以及回复隐藏/恢复/删除后的计数变化。生产构建通过。同一产物的 104 条弹幕浏览器回归及 78 项权限回归通过。测试使用独立数据库。内存不足时先暂停本地演示服务并限制构建并行度，按序运行验证后恢复演示服务。

此前通过 SSE open 后重新获取列表恢复。本轮改为数据库持久事件：迁移 0014 增加每篇论文的 `content_revision` 和 `paper_events`，数据库触发器将评论、计数、访问策略和默认版本变更与事件一并提交。应用统一按 paper → comment → user 顺序取锁。事务回滚、幂等重放或无变化的更新不生成新修订。事件仅含论文、版本、评论 ID、类型及修订信息，不广播正文、作者和 viewer 权限。

单实例分发器只查询有订阅的论文，每 500ms 读取一次持久事件，无订阅则停止。建连先注册待初始化订阅，再读取水位，补发后开启增量分发；此间的写入保存在事件表，避免握手漏消息。SSE 支持 `Last-Event-ID` 和 `after`，拒绝跨论文或非法游标；超出 1000 条、存在历史缺口或游标超前时发送 `stream.reset`。事件目前不自动删除，保留超过七天；清理运维任务尚未实现。

前端通过授权 REST 获取事件对应 DTO，按修订号和评论 ID 去重。删除会移除待播及在场弹幕；失权信号关闭连接并卸载阅读内容。正常重连使用补发，reset 才重新获取候选并保留已播集合。原始发文结果仍立即进入本地队列。

本轮使用 `.verify/production-discover` 生产构建与全新隔离 PGlite 库，实际通过：

## 新增需求：最简发现页

用户要求优先功能，界面和前端后续重新设计。本轮仅在站点顶部增加“发现”，使用时间切换链接和三个列表，不进行视觉重设计。

`/discover` 和 `/api/discover?period=all|today` 提供累计最多与今日榜单，每榜最多 20 项：

| 榜单 | 累计 | 今日榜单 |
| --- | --- | --- |
| 弹幕最多论文 | 当前可见、已开启弹幕的根评论数量 | 上一北京时间自然日发布的对应弹幕 |
| 获赞最多评论/弹幕 | 当前有效且非自赞、来自已验证用户的点赞 | 上一自然日新增，并在截止时仍有效的点赞；不按评论创建日期筛选 |
| 点击最多论文 | 上线后已记录的每日去重访问之和 | 上一自然日的每日去重访问 |

今日榜单以当天北京时间 00:00 为截止，例如 11 月 27 日统计 11 月 26 日 00:00（含）至 11 月 27 日 00:00（不含）。页面标出数据日期和截止时间，零点后新增数据进入次日榜单。迁移 0015 增加访问表与点赞有效区间，截止后取消点赞不会改写昨日得分；当前被隐藏、删除、私有化或下架的内容仍会撤出所有榜单。

访问仅在浏览器实际打开详情或阅读器后 POST 记录，不因服务端预取增加。访客使用签名 HttpOnly cookie；服务端以每日 HMAC 标识去重，不保存 IP 或原始访客标识。登录后按账号去重。新接口校验公开站点 Origin，事务内再次检查论文权限。历史点击无数据，无法回填；旧现存点赞按原创建时间回填区间，过去已取消的点赞无法恢复。

本轮 `node scripts/verify-discover.mjs` 实际通过：三类累计/每日排序、北京时间起止边界、零点后排除、旧评论在昨日获赞、截止后撤赞、匿名/自赞/未验证用户/私有/下架/隐藏隔离、12 次并发访问仅计一次、访客 cookie 去重及跨站请求拒绝。Chrome 验证首页导航进入发现页、时间切换、详情页实际访问入账，无前端异常。

本机演示库升级前另存完整备份，随后仅新增执行 0014、0015；保留原有五条演示弹幕。预览切换到本轮生产产物，首页与发现页 HTTP 200，导航入口存在。此操作不涉及用户的正式数据库。
